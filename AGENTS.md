# Blog repository instructions

## Working on posts

Before creating, editing, reviewing, or preparing a blog post for publication, read
`post-checklist.md` at the repository root and follow its applicable requirements.
Apply these rules to blog posts, not every Markdown document in the repository.

- Read relevant existing posts and the content schema before choosing a post location or tags.
- Apply the drafting requirements while writing; run publication checks when preparing a post
  for publication.
- Keep new and unfinished posts marked `draft: true`. Editing an already published post does
  not automatically require changing its draft status.
- Complete the Markdown before creating its hero image. Read the repository's `img-prompt.md`
  first and follow its visual instructions. If it is missing, report the missing dependency.
- When renaming an existing post, check links and references that depend on its slug.
- When preparing a draft for publication, follow the checklist's local verification sequence.
- Fix issues within the requested scope. Preserve the post's argument and the author's voice.
- Report publication checks as passed, failed, or not run, with a brief reason for failures
  and checks not run. Never claim verification without evidence.

Preparing a post for publication does not itself authorize deploying the website.
